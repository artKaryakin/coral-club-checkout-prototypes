# Стенд прототипов чекаута — структура и зоны ответственности

Документ для троих: **Артём (PM)**, **Ольга (дизайн)** и **её ИИ-агент**.
Место в репозитории: `docs/STAND.md`. Раздел 7 дублируется в `CLAUDE.md`, чтобы агент читал его вместе с конвенциями ДС.

---

## 1. Принцип: два слоя

| Слой | Владелец | Что это | Отвечает на вопрос |
|---|---|---|---|
| **Дизайн версий** | Ольга | Вёрстка и стили всех вариантов интерфейса | **Как выглядит** блок |
| **Ядро стенда** | Артём | Оси переключения, конфиг стран, локализация, состояния кейсов, подсказки адресов и данные карты | **Что показывается** внутри блока |

Слои не пересекаются по файлам. Ольга пушит правки дизайна — они применяются сразу, ничего согласовывать не нужно. Артём меняет наполнение — оно автоматически появляется во всех версиях.

**Ключевое следствие:** состав и порядок полей задаёт конфиг, а не вёрстка. Ольга оформляет поле, но не решает, есть ли оно в этой стране и где стоит.

## 2. Структура репозитория после реорганизации


## 3. Контракт между слоями

Единственное место, где слои соприкасаются. Соблюдается обеими сторонами.

### Как вариант получает поля

Вариант **не перечисляет поля вручную**. Он берёт готовый список у ядра и рендерит его циклом:

```vue
<!-- src/components/Variants/Inline/Cc3InlineAddressForm.vue — файл Ольги -->
<template>
  <div class="cc3-inline-address-form">
    <StandField
      v-for="field in fields"
      :key="field.key"
      :field="field"
      class="cc3-inline-address-form__field"
    />
  </div>
</template>

<script setup lang="ts">
import StandField from '@/stand/components/StandField.vue'
import { useStandFields } from '@/stand/composables/useStandFields'

const { fields } = useStandFields('address')
</script>
```

Ольга оформляет обёртку `.cc3-inline-address-form`, задаёт сетку, отступы, поведение на брейкпоинтах и внешний вид самого поля. Порядок и состав приходят сверху.

### Что отдаёт `useStandFields`

```ts
type StandField = {
  key: 'lookup' | 'street' | 'apartment' | 'postal' | 'city' | 'region'
     | 'country' | 'recipient_name' | 'recipient_phone'
  type: 'text' | 'select' | 'autocomplete' | 'phone'
  label: string          // уже переведён под текущую локаль
  autocomplete: string   // address-line1, postal-code, address-level2 …
  required: boolean
  autofilled: boolean    // заполняется по индексу, вручную не вводится
  options?: { value: string; label: string }[]
}
```

### Конфиг страны

```ts
// src/stand/config/countries.ts — файл Артёма
export const countries = {
  us: {
    locale: 'en',
    provider: 'loqate',
    fields: [
      { key: 'lookup',    type: 'autocomplete' },
      { key: 'street',    type: 'text',   required: true },
      { key: 'apartment', type: 'text' },
      { key: 'postal',    type: 'text',   required: true },
      { key: 'city',      type: 'text',   autofilled: true },
      { key: 'region',    type: 'select', autofilled: true },
    ],
  },
  // de, pl, cz, ru, kz …
}
```

Порядок массива = порядок полей на экране. Поменять порядок для Германии — правка одной строки, во всех вариантах сразу.

### Карта и подсказки

- **Данные** — зона Артёма: `useAddressSuggest`, `usePickupPoints`, выбор провайдера по стране, мок-режим.
- **Визуал** — зона Ольги: `Cc3Map`, `Cc3MapPin`, карточка пункта, список. Точки и подсказки приходят пропсами.

## 4. Оси стенда и ссылки

Три оси, все читаются из адреса:

```
#/{variant}/{country}/{case}
```

| Ось | Значения | Кто задаёт |
|---|---|---|
| `variant` | `prod` · `modal` · `inline` | Артём (список), Ольга (вёрстка) |
| `country` | `ru` · `kz` · `de` · `pl` · `cz` · `us` | Артём |
| `case` | `UC-01` … `UC-13` | Артём |

Язык берётся из страны. Переопределяется параметром `?locale=en` — для проверки локализации отдельно от набора полей.

Примеры:

```
#/inline/us/UC-03      инлайн, США, ввод адреса новым пользователем
#/modal/de/UC-07       модальный, Германия, добавление адреса при трёх сохранённых
#/prod/ru/UC-01        контрольная версия, Россия, пустая книга
```

Одна ссылка = одна полностью определённая конфигурация. Модератор ничего не кликает руками, в отчёте ссылка равна условиям наблюдения.

Текущая схема `#/modal/returning` перестаёт действовать: профиль `new`/`returning` поглощается кейсом — каждый кейс сам определяет стартовое состояние, включая наполнение адресной книги.

## 5. Инструкция Артёму

### Что делаешь

1. **Параметризовать `base` в `vite.config.ts`.** Сейчас захардкожен `/coral-club-checkout-prototypes/` — это ломает деплой в корень своего домена.

   ```ts
   base: process.env.VITE_BASE ?? (command === 'build' ? '/coral-club-checkout-prototypes/' : '/')
   ```

2. **Завести `src/stand/`** и перенести туда `useVariant.ts`, расширив до трёх осей.
3. **Написать `StandField.vue`** — на базе существующего `Cc3InputField`, с поддержкой состояния `autofilled` (визуально отличимо от введённого вручную).
4. **Заполнить `countries.ts`** по всем странам выборки и `cases.ts` по всем юз-кейсам.
5. **Подключить i18n** — словари по локалям, все подписи через ключи.
6. **Перенести подсказки адресов из спайка** в `useAddressSuggest` с обязательным мок-режимом: при недоступности провайдера отдаётся фиксированный набор подсказок, сессия не срывается.
7. **Панель модератора и вкладка кейсов** — за `?debug=1`. Респондент их не видит.
8. **Заменить `Cc3CheckoutCity.vue`** на поле из конфига. Отдельный компонент города — это ровно тот хардкод, который мешает версионности.

### Как запускать

**Локально:**
```bash
nvm use && npm install
npm run dev          # http://127.0.0.1:5173
```

**Прямо из гита** — уже работает: push в `main` → GitHub Actions собирает и публикует на Pages.
Адрес: `https://olgaperovamisc81.github.io/coral-club-checkout-prototypes/`

**На своём сервере:**
```bash
git clone https://github.com/olgaperovamisc81/coral-club-checkout-prototypes.git
cd coral-club-checkout-prototypes
nvm use && npm ci
VITE_BASE=/ npm run build     # результат в dist/
```

Дальше `dist/` раздаётся статикой. Минимальный nginx с закрытым доступом:

```nginx
server {
    listen 443 ssl;
    server_name stand.example.com;

    root /var/www/checkout-stand/dist;
    index index.html;

    auth_basic "Prototype";
    auth_basic_user_file /etc/nginx/.htpasswd;

    add_header X-Robots-Tag "noindex, nofollow" always;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`try_files … /index.html` обязателен: приложение одностраничное, без него прямые ссылки на кейсы отдадут 404.

Автодеплой на сервер — тем же workflow, добавив шаг `rsync` после `npm run build`.

### Режим работы с git

- Ольга пушит в `main` как сейчас — её привычка не меняется.
- Артём работает в ветках `stand/<что-делаем>` и мержит через PR.
- Перед началом работы всегда `git pull` — в `main` могли приехать правки дизайна.
- Зоны не пересекаются, поэтому конфликтов быть не должно. Если конфликт возник — значит нарушено разделение зон, разбираться надо с этим, а не с самим конфликтом.

## 6. Инструкция Ольге

### Твоя зона — целиком твоя

`src/components/Variants/*`, `src/components/Field`, `src/components/Icon`, `src/components/Map`, `src/styles/*`, `src/assets/*`, `design-references/*`.

Здесь можно всё: менять вёрстку, стили, структуру компонентов, добавлять свои. Пушишь в `main`, GitHub Pages пересобирается автоматически, изменения видны по ссылке через пару минут. Ничего согласовывать не нужно.

### Чего делать не нужно

- **Не добавлять поля формы руками.** Появилось новое поле в Figma — напиши Артёму, какое поле и для какой страны. Он добавит в конфиг, поле появится во всех вариантах сразу. Если добавить `<input>` в шаблон, оно будет только в одной версии и сломает сравнение концептов.
- **Не задавать порядок полей вёрсткой.** Порядок приходит из конфига и меняется от страны к стране. Поэтому в CSS **нельзя использовать `:nth-child`, `+` и `~`** для полей формы — отступы задаются самому полю.
- **Не хардкодить тексты подписей полей.** Они приходят переведёнными. Заголовки блоков, подсказки и кнопки — можно, но лучше тоже через ключи.
- **Не трогать `src/stand/`** — это ядро стенда.

### Если нужно новое поле

Одно сообщение Артёму:

> Нужно поле «Домофон», текстовое, необязательное, только для RU и KZ, после «Квартира».

Дальше оно появляется само.

### Обязательное к каждой версии

Каждый вариант должен уметь отрисовать все состояния, которые встречаются в юз-кейсах:

1. Книга адресов пуста.
2. Один сохранённый адрес.
3. Четыре сохранённых адреса.
4. Восемь и больше адресов — со скроллом и поиском.
5. Форма добавления адреса, пустая.
6. Поля, заполненные автоматически по индексу — визуально отличимые от введённых вручную.
7. Ошибка валидации на поле.
8. Адрес не найден в подсказках, ручной ввод.
9. Способ доставки недоступен для адреса.
10. Получатель отличается от владельца аккаунта.

Проверять по ссылкам вида `#/inline/de/UC-07` — состояние подставляется само, вручную набивать ничего не нужно.

## 7. Инструкция агенту (дублируется в `CLAUDE.md`)

При работе в этом репозитории:

1. Прочитать `CLAUDE.md` и `docs/STAND.md` перед первой правкой в сессии. При расхождении с Figma прав `CLAUDE.md`.
2. **Не создавать и не удалять поля формы.** Поля приходят из `src/stand/config/countries.ts` и рендерятся через `StandField`. Если макет требует нового поля — не добавлять его в шаблон, а сообщить дизайнеру формулировкой: какое поле, тип, обязательность, для каких стран, после какого поля.
3. **Не редактировать ничего в `src/stand/`.** Это ядро стенда, зона PM.
4. **Не задавать порядок полей вёрсткой.** Не использовать `:nth-child`, `+`, `~` для полей формы. Отступы — на самом поле.
5. **Не дублировать разметку формы между вариантами.** Общее поведение живёт в `StandField`, различается только оформление обёртки.
6. **Не хардкодить подписи полей** — они приходят из локализации.
7. При вёрстке по Figma: настоящие `<input>` и `<label for>`, никакого `position: absolute` для раскладки, никаких фиксированных ширин, никаких имён автослоёв Figma в классах. Имя класса = имя компонента, по конвенции `CLAUDE.md`.
8. **Не перегенерировать проект целиком.** Изменился один блок — правится один файл. Коммит, в котором изменены все файлы разом, считается ошибкой.
9. Не подключать сторонние библиотеки. Не использовать TailwindCSS.
10. Перед коммитом: `npm run type-check`, `npm run lint`, `npm run lint:style`.
11. Коммиты атомарные, сообщения на русском в формате `вариант: что сделано`. В сообщении указывать ссылку на фрейм Figma и дату макета.
12. Если задача требует нарушить любое из правил выше — не нарушать, сообщить дизайнеру и остановиться.
